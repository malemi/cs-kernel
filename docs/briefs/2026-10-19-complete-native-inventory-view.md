# Complete native inventory view

## Intent and evidence

Make mandatory ordinary discovery inspection practical without weakening coverage
or increasing model budgets. V22 remains FAILED: all six phases and strict native
lifecycle passed, but the model voluntarily skipped its 98,755-byte discovery
artifact. Only grep was attempted; native completion cost USD1.8873254 was not a
budget exhaustion. No selected root was worked. Read/dd instructions have no
proven literal contradiction. Evidence is retained under
`/home/mal/.local/share/mrcall-operational-evidence/2026-10-19/ordinary-assignment-recovery-v22/`,
particularly `inspection-contract-audit.json` and its command/budget audits.

This brief authorizes no implementation, installation, provider call or paid
retry. Review framing first; a separately reviewed plan must precede source work.

## Proposed representation and scope

Use a source-owned, deterministic, lossless structural representation of the
complete original discovery object. Prefer repeated-object/string interning and
columnar records over a semantic summary. No nested business evidence is omitted:
references replace duplicate bytes, not evidence. If this cannot produce a
materially smaller comprehensible native view on V22, the approach fails its
free acceptance gate and must be reframed before implementation or paid testing.

Proposed versioned envelope:

- `schema`, `raw_sha256`, `view_payload_sha256`, raw byte length, owner UID,
  exact process/start ancestry, nonce and current native invocation binding.
  View hash excludes its own hash slot; canonical serialization is specified.
- `groups`: every original discovery key in original order, with its actual
  type, row count where applicable, and an ordered sequence of row references.
  Scalar `assignment_incomplete`, `note`, `read_incomplete`, and `crm_note`
  retain their exact values. Unknown fields are losslessly represented or cause
  explicit refusal; they are never silently dropped.
- `records`: ordered column definitions plus typed values. Each original field
  remains accessible by an unambiguous typed reference. Null, absent, false,
  empty array and empty object remain distinct. Literal strings cannot be
  confused with references; references are tagged and acyclic.
- `values`: shared exact string/object values in first-occurrence order, with
  explicit IDs and reference definitions. Every reference resolves inside this
  view; raw-file lookup is not needed to reconstruct discovery or understand a
  hold. Cycles, dangling references, duplicate IDs and ambiguous encodings fail.
- `inspection`: exact current view path/hash/length and bounded page offsets,
  total pages and remaining uncovered byte ranges. These are source-produced
  facts, never model attestations. Metadata cannot claim native inspection.

All top-level group membership and duplicate occurrences remain explicit:
`open`, `handled`, `escalated`, `operational_fixture_discovery`, `human_work`,
`assignment_audit`, `assignment_incomplete`, `resumed`, `automatic`, `courtesy`,
`note`, `read_incomplete`, `crm_note`, `triage_workset`, and future keys.
Every row retains all present email/name/subject/date/wait/state/reason/thread
fields, escalation details, workset revision and other original fields.
Assignments retain actor/space/source-owner identity, authoritative/component
roots, completeness/state/hold, tasks/events, current and covered inbound/message
IDs, reply evidence including provider identities/digests/judgements/reasons,
route digest and provenance. Shared nested proof is represented once, with exact
references at every original occurrence. There is no omitted nested proof whose
irrelevance must be trusted.

`triage_workset` remains exact: completeness, limit, ordered selected roots with
revision/sources, ordered deferred roots/reasons/sources and every held
root/reason/source. Preserve source grouping even when the same root appears
multiple times. No fixture preference, reordering, filtering, count-only entry,
digest-only entry or truncation is allowed. The model must inspect all view
bytes including all reference definitions before any effect. Selected-root deep
reads and factual evidence remain required; the view grants no action authority.

Retain canonical public CLI stdout, the protected discovery.json and its raw
receipt byte-identical; create the view as a separate private artifact.
Retain the full original private raw artifact unchanged. Independently decode
and compare the view to that exact raw object, including key/group/array order,
fields, typed values and all bindings. Hash equality alone is not semantic parity.
The independent Actor consumer must recompute parity and native coverage rather
than trusting a producer boolean or receiving only a digest.

## Inspection contract

Choose one explicit bounded native paging protocol prospectively in the plan;
its command syntax, byte semantics and independent recognizer must agree.
Existing exact Bash dd semantics can be retained for the new artifact, with
bounded pages and overlapping offsets; built-in Read is not implicitly accepted
as byte coverage. Do not mix task-output Read guidance with discovery proof.
Expose deterministic remaining offsets/page progress after actual matching
native tool results; false, stale, partial, reordered or fabricated receipts do
not discharge inspection. Post-terminal health must still fail incomplete
inspection. Original raw inspection may remain a fully strict compatibility
route; accepting the compact view requires complete exact parity first.

No engine assignment/send guard, ownership boundary, workset scheduler, model
cap, permission, campaign/signup behavior or six-phase requirement changes.
No polling loop or background completion guess is introduced. Any lifecycle
integration must preserve genuine native process/tool/result binding and all
existing fail-closed cases. Alarm generation remains deterministic and zero-model.

## Acceptance and negative controls

Before installation or any requested paid acceptance:

1. Offline replay of actual immutable V22 raw discovery yields exact independent
   round-trip/parity, all groups/counts/occurrences/fields/order/holds/selected
   roots, and a materially smaller view. Report actual byte/page reduction and
   reference expansion; no claimed operational success follows from compression.
2. Demonstrate native readability on the actual view: explicit schema legend,
   resolvable references and bounded deterministic page plan, without a second
   semantic interpretation layer. The reviewer must reject an opaque compact
   codec whose complete meaning requires ad-hoc shell/Python reconstruction by
   the model. If lossless compression cannot satisfy this, stop for reframing.
3. Adversarial cases reject deleted or duplicated rows, swapped groups/order,
   changed selected/deferred/held membership, forged counts, altered reasons or
   eligibility/completeness/owner/root/source/provider evidence, unknown-field
   loss, null/absent confusion, bad references and modified raw/view hashes.
4. Wrong owner/process/start/nonce/source/native invocation, stale view, producer
   pair substitution, clipped/grep-only/partial/missing-page/native-result
   tampering and effects before complete inspection all remain rejected.
5. Preserve existing strict native lifecycle, six phases, raw read failures,
   business observation limits and action-failure negatives. A source/config
   component PASS is not ordinary/provider acceptance. No signed PASS or release
   can be inferred from offline fixtures.

## Constraints and unresolved design decisions

Both maintained clones need the same neutral capability. Company data stays in
Settings/manifest; no company-specific kernel branch. Existing protected drafts,
cron, enrollment, locks, ordinary budgets, engine controls and raw artifacts are
preserved. No automatic paid continuation or budget increase is authorized.

The plan must fix the exact encoding, independent verifier ownership, secure
artifact creation, size/reference bounds, native progress emission mechanism,
inspection recognizer, installation/rollback and actual free tests. This brief
intentionally makes feasibility an offline gate: failure to shrink a fully
readable lossless view must not become permission to omit evidence or retry a
prompt at cost.
