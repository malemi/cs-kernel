# Protected originals in normal operator acceptance

The exact-draft live acceptance requires actual scheduled generation and provider
outcomes on both maintained operators. The existing Desktop operational contract
explicitly authorizes reciprocal engineering fixtures, normal model calls and
installed cron execution. The first real run fails: support never processes the
fresh original and Café times out while gathering unrelated work. Installed
workflow instructions have an unconditional SELF prohibition and neither consume
protected discovery metadata nor prioritize the original. Truncated queue output
also hides that metadata. The protected fixture code already independently checks
the exact original against a root-owned receipt/enrollment; mail text is never
an authorization source.

Make this existing test authority visible and usable through the canonical
operator/triage workflow. Process only the exact provider-verified originals in
`operational_fixture_discovery` first, then finish normal recurring work. The
ordinary engine remains the author, through its usual dossier, exact-thread
assignment, source, pause, suppression, history and send/draft checks. Preserve
all customer holds; one unknown thread does not authorize that thread or hold an
independently complete one. Output is read completely in bounded sections,
without cutting off evidence or candidate arrays.

The only authority exception is the already owner-authorized protected original
to the SELF-contact prohibition. A dossier refusal caused solely by that same
SELF prohibition must be handled consistently with the explicit test authority;
no other dossier STOP or sending precondition is waived. If another refusal
applies, keep it and repair the test prerequisites without hiding it. No model,
mail subject/body, arbitrary setting or unverified callback can create the
exception. Expiry and enrollment cleanup remove the exception automatically;
acknowledgements and all other SELF correspondence remain excluded.

Scope: additive canonical workflow instructions and corresponding preserved
clone surfaces, plus narrowly necessary proof/runner integration. Keep these
operational-test changes as a separately reviewed overlay; the pure exact-draft
public tag excludes unrelated source. Existing permissions, send mode, schedules,
company rules, budgets and manual customer records stay unchanged. Normal cron
runs may process existing work only under their pre-existing authority. Never
compose the expected response in the runner or inject a computed answer. Never
use direct SMTP for a generated reply or fabricate a provider-visible draft.

Acceptance requires all three hosts to resolve the same canonical workflow
bytes, all previous guards to survive, protected metadata to be complete and
provider-bound, and a fresh real run with the exact tested kernel/engine source.
Support must produce the correct contextual reply independently received by the
original sender; Café must produce a usable provider draft with its exact engine
ID and selected owner headers, with no sent response. Duplicate, wrong owner,
held fixture, missing answer, zero fixture work, failed/unfinished job or timeout
cannot pass. A legitimate reported customer hold is distinguished from an
unavailable whole-run operation only using real terminal/tool/phase evidence;
removing a regex or trusting free-text success is insufficient. Retain failed
runs and never replay an uncertain submission. Public publication and customer
cleanup remain separately authorized boundaries.
