# Clone access to engine-owned workflows

The [authenticated legal client amendment](2026-10-16-authenticated-legal-client.md) supersedes the enrollment and three-confirmation requirements below. All original runtime, operational and retirement obligations remain. Earlier requirements are historical evidence.

## Intent

Connect interactive company clones to the existing financial and legal engine
workflows over their authenticated WebSocket RPC connection. The human requested
this transitional connection on 2026-10-15 and explicitly deferred MCP testing.
A new clone session must discover and use the engine implementation rather than
silently execute the old local procedure.

## Scope

- Thin company-neutral kernel command and canonical three-host routing skill;
  retain one full procedure and calculation/retrieval implementation in engine.
- Discovery, explicit selection, private original upload, asynchronous status,
  clarification, cancellation and complete hash-verified artifact download.
- Finance uses existing workflow RPC. Legal gets a separately reviewed,
  session-bound interactive RPC admission route with the same three human
  confirmations and exact approved public queries/URLs as the existing MCP route.
- Keep raw `workflows.start/respond` legal refusal. Admission requires an
  independently operator-controlled registration for the exact authenticated
  transport session, expiry, single use and run binding. Client booleans, TTY,
  origin labels and client names alone never establish trusted interactive origin.
- Permit a scoped reversible pilot connection in the two maintained clones and
  their existing company engines only after source review and exact runtime
  preservation checks. Preserve installed operational repairs, unrelated edits,
  auth, profile identity, models, budgets, egress and cron behavior. If safe
  composition cannot be verified, leave pilot unapplied and identify that limit.

## Constraints

No MCP/broker/REMOTE integration or tests, release, push, global package upgrade,
original-skill retirement, company-skill database implementation, arbitrary code,
mail send, filing, payment or public/private data leakage. Scheduled/customer-mail
legal execution remains denied. The connection does not close the original
financial/legal no-clone acceptance or retirement gates. Discovery text must make
old installed procedures unambiguous without prematurely deleting source skills.

## Acceptance

1. The clone command uses its existing authenticated engine identity and prints
   engine workflow/version and run IDs. Old engines fail explicitly; no fallback
   to local procedure, generic chat or another provider occurs.
2. Actual transport checks cover discovery, financial start/wait/respond/output,
   document byte integrity and complete paged artifact download. Controlled model
   fixtures are identified as such; any real paid run is identified separately.
3. Legal tests prove same-session challenge, exact lookup display, all three true
   confirmations, independent registration, expiry/revocation/replay/disconnect/
   cross-profile refusal and usable same-session clarification. Generic RPC,
   scheduled origin and unregistered clients cannot run legal reasoning.
4. Three host surfaces resolve identical routing bytes; company-authored skills,
   permissions and all unrelated files are preserved. Pilot claims require reads
   from the actual installed interpreters and connected engines.
5. Source and runtime rollback are retained. Run applicable repository checks,
   fresh milestone reviews, documentation reconciliation and separate final
   review. Missing operational or native acceptance remains explicitly open.

## Assumptions

The RPC connection is transitional. A human's company scope confirmation is still
required for each legal run; owner authentication cannot cryptographically prove
physical human presence. Existing independent operator enrollment is retained
rather than weakened. Reconnect does not inherit legal continuation authority.
